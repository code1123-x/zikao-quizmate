# 自考刷题工具 · 设计方案

> 项目代号：`quizmate` ｜ 目标用户：你自己（可扩展到同学多人）｜ 版本：v0.1 设计稿
> 交付物：本设计文档 + `prototype/mockup.html`（可点击的高保真界面原型）

---

## 0. 一页速览

| 项 | 结论 |
|---|---|
| 产品形态 | **本地服务 + 浏览器界面**：双击启动，电脑浏览器打开，手机连同一 Wi-Fi 扫码即刷 |
| 技术栈 | Java 21 + Spring Boot 3 + SQLite（后端） / Vue 3 + TypeScript + Vite（前端） |
| 为什么不是 JavaFX / Electron | JavaFX 无法复用到手机；Electron 不是 Java 生态且体积大。浏览器方案一套 UI 同时覆盖 PC 和手机 |
| 数据存放 | 全部在你自己的电脑上：`data/quiz.db` + `data/media/`，可一键备份成 zip |
| 核心闭环 | **双闭环**：① 刷题：导入 → 练习 → 判分 → 错题 → 间隔复习；② 学知识点：卡片流 → 即测 → 掌握度 → 反查 |
| 难点 | **题库结构化**（Word/PDF 排版千奇百怪）和 **主观题无法自动判分**，方案里各有对应设计 |
| 预估工期 | 业余时间约 2 周（M0~M4），最小可用版本 3~4 天 |

## 1. 需求拆解

### 1.1 你的原始诉求

1. 自考复习刷题
2. Java 开发
3. 题库资料在自己百度网盘里（Excel / Word / PDF / 文本 / HTML / 截图）
4. 支持多学科
5. 交互要好用
6. 参考已有工具

### 1.2 拆成可执行的功能清单

| 模块 | 必备能力 | 说明 |
|---|---|---|
| 学科管理 | 多学科、**名称自定义 + 别名/课程代码**、章节树、考试日期、颜色标识 | 各地各专业科目不同，学科必须完全自定义；别名用于导入时自动认领 |
| 题库 | 题型全覆盖、富文本/公式/图片、标签、来源年份 | 题干统一用 Markdown 存储 |
| **知识点** | 章节化卡片、要点/原文、关联真题、卡片流学习、掌握度 | **与刷题并列的一级模块**，不是题目的附属 |
| 导入 | 4 种格式适配 + 人工校对工作台 + 去重 + 批次回滚 | **本项目最花时间的地方** |
| 练习 | 章节 / 随机 / 模考 / 错题 / 收藏 / 背题 / 每日复习 | 7 种模式共用同一个答题引擎 |
| 判分 | 客观题自动、主观题自评、多选计分策略可配 | 自考多选一般"全对才得分"，但要可配置 |
| 记忆 | 错题本 + 间隔重复（SM-2）+ 待复习队列 | 决定"刷完就忘"还是"真的记住" |
| 统计 | 打卡热力图、正确率趋势、章节掌握度 | 首页给"今天该干什么"，而不是一堆图表 |
| 运维 | 一键启动、局域网二维码、自动备份、导出 | 非功能但决定你愿不愿意天天用 |

## 2. 参考产品与借鉴点

| 产品 | 值得借鉴 | 不照搬 |
|---|---|---|
| **粉笔 / 万题库** | 一屏一题的专注模式、答题卡网格跳题、模考倒计时、错题本按章节归类 | 广告和社交，不需要 |
| **考试宝 / 考试星** | Excel 模板导入、试卷结构（大题+分值） | 后台管理太重 |
| **Anki** | 间隔重复调度、卡片"会/不会"极速判定 | 卡片太碎，不适合成套刷题 |
| **Quizlet** | 学习模式切换（卡片/测试/配对）、移动端手势 | 题库以自建卡片为主 |
| **墨墨背单词** | 每日任务量、连续打卡、复习队列的"欠账"提示 | 商业化太重 |
| **Obsidian** | 多学科用"库/文件夹/标签"三层组织 | 不适合答题场景 |

**结论**：做成「粉笔的答题体验 + Anki 的记忆调度 + 考试宝的导入能力」，但只服务一个人，去掉所有后台管理复杂度。

## 3. 总体架构

### 3.1 部署形态

```
                    ┌──────────────────────────────┐
   手机浏览器 ──────▶│                              │
   (同一 Wi-Fi)      │   Spring Boot (8080)         │
                    │   ├─ /api/**    REST         │
   电脑浏览器 ──────▶│   ├─ /          Vue SPA      │
                    │   ├─ /media/**  图片/附件    │
                    │   └─ /h2-console (仅 dev)    │
                    └───────────┬──────────────────┘
                                │
                     ┌──────────▼──────────┐
                     │  data/              │
                     │   quiz.db (SQLite)  │
                     │   media/  (题目图片) │
                     │   imports/ (原始文件)│
                     │   backups/ (每日备份)│
                     └─────────────────────┘
```

- 单进程：后端顺带把前端静态资源一起打包，**一个 jar 跑起来就是完整应用**
- 手机访问：首页显示 `http://192.168.x.x:8080` 的二维码，扫码直接用（Windows 防火墙首次需放行）
- 账号：局域网内可能被同 Wi-Fi 的人看到，做一个**单账号登录 + 记住我**即可；数据按 `user_id` 预留，将来多人不返工

### 3.2 为什么选这套

| 层 | 选型 | 版本 | 理由 |
|---|---|---|---|
| JDK | **JDK 21 (LTS)** | 21 | ⚠️ 你机器现在是 Java 8，Spring Boot 3 跑不了，必须装 21；后续可用 jlink 打包，换电脑不用装 Java |
| 后端框架 | Spring Boot | 3.3.x | 生态最全，POI/PDFBox 集成顺手，自带静态资源托管 |
| 数据库 | SQLite（xerial JDBC） | 3.45+ | 零安装、单文件、备份=复制文件；WAL 模式下读性能足够。题量 10 万级完全够用 |
| ORM | MyBatis-Plus | 3.5.x | 比 JPA 更好控制 SQL 和 SQLite 方言，分页/批量插入方便 |
| 迁移 | Flyway（sqlite 模块） | 10.x | 表结构可版本化，改字段不慌 |
| 文档解析 | Apache POI / PDFBox / jsoup / Tika | 5.3 / 3.0 / 1.18 / 2.9 | 覆盖 docx/xlsx/**pptx**、PDF 文本、HTML；Tika 做文件类型嗅探（防扩展名与真实格式不符） |
| 前端 | Vue 3 + TypeScript + Vite | 3.5 / 6 | 上手快、生态成熟、打包体积小 |
| 状态/路由 | Pinia + Vue Router | - | 标准组合 |
| UI | Tailwind CSS + shadcn-vue + lucide 图标 | - | 不用组件库的重样式，答题页排版可控；响应式一改就适配手机 |
| 图表 | ECharts | 5.x | 热力图、趋势图现成 |
| 富文本 | markdown-it + DOMPurify + KaTeX | - | 题干里的公式、图片、加粗都能显示 |
| 打包 | jpackage / jlink | JDK 21 自带 | 生成 `quizmate.exe`，双击即开，自动打开浏览器 |
| 二维码 | ZXing | 3.5 | 首页生成局域网地址二维码 |

> 备选：如果你更熟 React，可以换 Next.js/React；但 Vue 在"一个人快速做出好看的答题界面"这件事上性价比最高。

## 4. 数据模型

### 4.1 ER 关系

```
subject 1 ──< chapter 1 ──< question >── paper_question >── paper
                │                 │
                │                 ├──< answer_record
                │                 ├──< review_state   (间隔重复)
                │                 ├──< favorite
                │                 ├──< note
                │                 └──< errata        (纠错反馈)
                │
             practice_session ──< answer_record
```

### 4.2 关键表设计（SQLite DDL 摘录）

```sql
-- 学科
CREATE TABLE subject (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  code        TEXT UNIQUE,              -- 00015 自考课程代码
  name        TEXT NOT NULL,
  color       TEXT DEFAULT '#4F46E5',
  exam_date   TEXT,                     -- 2026-04-12，首页倒计时用
  archived    INTEGER DEFAULT 0,
  sort        INTEGER DEFAULT 0,
  created_at  TEXT NOT NULL
);

-- 章节（支持多级，path 便于查子树）
CREATE TABLE chapter (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  subject_id  INTEGER NOT NULL REFERENCES subject(id) ON DELETE CASCADE,
  parent_id   INTEGER REFERENCES chapter(id),
  name        TEXT NOT NULL,
  path        TEXT NOT NULL,            -- "/3/12/" 前缀匹配取整章题目
  depth       INTEGER DEFAULT 0,
  sort        INTEGER DEFAULT 0
);

-- 题目（核心表）
CREATE TABLE question (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  subject_id  INTEGER NOT NULL REFERENCES subject(id),
  chapter_id  INTEGER REFERENCES chapter(id),
  type        TEXT NOT NULL,            -- SINGLE/MULTIPLE/JUDGE/FILL/TERM/SHORT/CALC/ESSAY
  stem        TEXT NOT NULL,            -- Markdown：支持 ![](media/xx.png) 和 $公式$
  options     TEXT,                     -- JSON: [{"key":"A","text":"..."}, ...]
  answer      TEXT NOT NULL,            -- 规范串：'B' / 'ABD' / '对' / '答案1|答案2'
  analysis    TEXT,                     -- 解析（Markdown）
  difficulty  INTEGER DEFAULT 3,        -- 1~5，错得多自动上调
  score       REAL DEFAULT 1,
  source      TEXT,                     -- "2024年4月真题"
  year        INTEGER,
  tags        TEXT,                     -- JSON: ["第三章","易错"]
  hash        TEXT,                     -- 归一化题干 SHA1，用于去重
  status      TEXT DEFAULT 'ACTIVE',    -- ACTIVE/DISABLED/DRAFT
  import_batch_id INTEGER,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE INDEX idx_q_subject_chapter ON question(subject_id, chapter_id);
CREATE UNIQUE INDEX uk_q_hash ON question(subject_id, hash);

-- 试卷 / 试卷题目（模考用）
CREATE TABLE paper (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  subject_id INTEGER NOT NULL,
  title TEXT NOT NULL,
  type TEXT DEFAULT 'MOCK',             -- MOCK 模拟卷 / REAL 真题 / CUSTOM 自组卷
  year INTEGER, duration_min INTEGER DEFAULT 150, full_score REAL DEFAULT 100,
  created_at TEXT
);
CREATE TABLE paper_question (
  paper_id INTEGER NOT NULL, question_id INTEGER NOT NULL,
  seq INTEGER, score REAL,
  PRIMARY KEY (paper_id, question_id)
);

-- 练习会话（断点续答 + 结果页都靠它）
CREATE TABLE practice_session (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  subject_id INTEGER NOT NULL,
  mode TEXT NOT NULL,                   -- CHAPTER/RANDOM/EXAM/WRONG/FAVORITE/REVIEW/RECITE
  paper_id INTEGER,
  config TEXT,                          -- JSON：题量/章节/是否乱序/是否立即判分
  question_ids TEXT,                    -- JSON 数组，锁死本次题目顺序
  cursor INTEGER DEFAULT 0,             -- 断点续答
  status TEXT DEFAULT 'DOING',          -- DOING/DONE/ABANDONED
  correct_count INTEGER DEFAULT 0,
  total_count INTEGER DEFAULT 0,
  cost_ms INTEGER DEFAULT 0,
  started_at TEXT, finished_at TEXT
);

-- 答题记录（统计的唯一事实来源）
CREATE TABLE answer_record (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id INTEGER NOT NULL,
  user_id INTEGER NOT NULL,
  question_id INTEGER NOT NULL,
  user_answer TEXT,
  is_correct INTEGER,                   -- 1 对 / 0 错 / NULL 主观题未评
  score REAL,
  self_rating TEXT,                     -- 主观题：MASTER/VAGUE/NONE
  cost_ms INTEGER,
  answered_at TEXT NOT NULL
);

-- 间隔重复状态（SM-2）：题目和知识点共用一张表
CREATE TABLE review_state (
  user_id INTEGER NOT NULL,
  item_type TEXT NOT NULL,              -- QUESTION / KNOWLEDGE
  item_id INTEGER NOT NULL,
  ease REAL DEFAULT 2.5,
  interval_days INTEGER DEFAULT 0,
  reps INTEGER DEFAULT 0,
  lapses INTEGER DEFAULT 0,
  due_at TEXT,
  last_result TEXT,                     -- CORRECT/WRONG/VAGUE
  updated_at TEXT,
  PRIMARY KEY (user_id, item_type, item_id)
);
CREATE INDEX idx_review_due ON review_state(user_id, item_type, due_at);

-- 学科别名（"马原" / "马克思主义基本原理" / "03709" 都能认出来）
CREATE TABLE subject_alias (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  subject_id INTEGER NOT NULL REFERENCES subject(id) ON DELETE CASCADE,
  alias TEXT NOT NULL,
  UNIQUE(subject_id, alias)
);

-- 资料库：一份原始文件 = 一条 material
CREATE TABLE material (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  subject_id  INTEGER REFERENCES subject(id),
  type        TEXT NOT NULL,        -- REAL_PAPER/EXERCISE/BOOK/LECTURE/NOTES/OTHER
  title       TEXT NOT NULL,
  file_name   TEXT NOT NULL,
  ext         TEXT,
  sha1        TEXT UNIQUE,          -- 同一份资料重复下载直接跳过
  size_bytes  INTEGER,
  page_count  INTEGER,
  confidence  REAL,                 -- 自动识别置信度 0~1
  status      TEXT,                 -- PENDING/PARSING/READY/FAILED/ARCHIVED
  produced    TEXT,                 -- JSON: {"questions":128,"blocks":460,"points":23}
  meta        TEXT,                 -- JSON: 年份/版次/来源
  imported_at TEXT
);

-- 原文块：教材/讲义的段落，用于"查看教材原文"和全文检索
CREATE TABLE material_block (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  material_id INTEGER NOT NULL REFERENCES material(id) ON DELETE CASCADE,
  chapter_id  INTEGER REFERENCES chapter(id),
  seq         INTEGER,
  page_no     INTEGER,
  heading     TEXT,
  content     TEXT NOT NULL,        -- Markdown
  char_len    INTEGER
);
CREATE INDEX idx_block_material ON material_block(material_id, seq);
-- 全文检索（SQLite FTS5，中文用 trigram 分词器）
CREATE VIRTUAL TABLE block_fts USING fts5(
  heading, content, content='material_block', content_rowid='id', tokenize='trigram');

-- 知识点卡片（从讲义/笔记/解析里抽出来）
CREATE TABLE knowledge_point (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  subject_id INTEGER NOT NULL,
  chapter_id INTEGER,
  title      TEXT NOT NULL,
  summary    TEXT,
  source_block_id INTEGER REFERENCES material_block(id),
  tags       TEXT,
  created_at TEXT
);

-- 题目 ↔ 资料（溯源：这道题出自哪份真题第几页）
CREATE TABLE question_source (
  question_id INTEGER NOT NULL,
  material_id INTEGER NOT NULL,
  block_id    INTEGER,
  page_no     INTEGER,
  PRIMARY KEY (question_id, material_id)
);

-- 题目 ↔ 知识点
CREATE TABLE question_kp (
  question_id       INTEGER NOT NULL,
  knowledge_point_id INTEGER NOT NULL,
  weight            REAL DEFAULT 1,
  PRIMARY KEY (question_id, knowledge_point_id)
);

-- 后台任务（扫描/解析/入库，带进度）
CREATE TABLE import_job (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  type       TEXT,                  -- SCAN/PARSE/COMMIT
  payload    TEXT,
  progress   INTEGER DEFAULT 0,
  status     TEXT,                  -- QUEUED/RUNNING/DONE/FAILED
  message    TEXT,
  created_at TEXT, finished_at TEXT
);

-- 其它：favorite / note（题目笔记）/ errata（纠错）/ app_user
```

### 4.3 几个设计要点

- **题干存 Markdown 而不是 HTML**：导入时做一次转换，展示时渲染；图片用相对路径，便于整体搬迁
- **`question_ids` 固化在会话里**：刷新、换设备、第二天接着答，题目和顺序都不变
- **`hash` 去重**：题干去掉空白/标点/序号后取 SHA1，同章节重复导入直接进"疑似重复"列表人工确认
- **`errata` 表**：刷题时发现答案错了，点"报错"，记录到待修正清单，比在 Word 里翻半天强

## 5. 题库导入流水线（重点）

这是整个项目 60% 的工作量。核心原则：**自动解析只做到 80%，剩下 20% 用"校对工作台"高效人工兜底**，不要幻想 100% 全自动。

### 5.1 流程

```
 上传原始文件
      │
      ▼
 ┌─────────────┐   自动识别   ┌──────────────────────────────┐
 │ 格式探测    │─────────────▶│ 适配器                        │
 │ xlsx/docx/  │              │  Excel / Word / PDF / HTML    │
 │ pdf/html/图片│              │  图片 → OCR（可选）           │
 └─────────────┘              └──────────────┬───────────────┘
                                             │ 统一中间模型
                                             ▼
                              ParsedQuestion { no, type, stem,
                                options[], answer, analysis,
                                chapterHint, source, rawText }
                                             │
                                             ▼
                                   ┌──────────────────┐
                                   │ 校验 & 去重       │
                                   │ 缺答案/选项越界/  │
                                   │ 重复题/空题干     │
                                   └────────┬─────────┘
                                            ▼
                                   ┌──────────────────┐
                                   │ 校对工作台（人工）│
                                   │ 左原文 右表单     │
                                   └────────┬─────────┘
                                            ▼
                                   ┌──────────────────┐
                                   │ 入库（批次事务）  │
                                   │ 可整批回滚        │
                                   └──────────────────┘
```

### 5.2 Excel / CSV（优先级最高，最省事）

给一份**标准模板**（同时提供"列名自由映射"，你的旧表格不用改）：

| 学科 | 章节路径 | 题型 | 题干 | 选项A | 选项B | 选项C | 选项D | 选项E | 选项F | 答案 | 解析 | 难度 | 来源 | 年份 | 分值 | 标签 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 马克思主义基本原理 | 第三章/实践与认识 | 单选 | 实践是认识的基础，因为… | 认识决定实践 | 实践是认识的来源 | … | … | | | B | 实践决定认识… | 3 | 2024年4月真题 | 2024 | 2 | 易错,第三章 |

- 答案格式约定：单选 `B`、多选 `ABD`（顺序无所谓）、判断 `对`/`错`、填空 `答案1|同义答案2`、主观题填参考答案全文
- 章节路径用 `/` 分隔，不存在则自动创建
- 表头别名：`题目`/`题干`/`问题` → stem；`正确答案`/`答案` → answer；`选项1`/`A` → 选项A …
- 大文件用 POI 的 **SAX 事件模式**读，10 万行也不会 OOM

### 5.3 Word / PDF / HTML（规则解析）

统一先抽成"纯文本行序列"，再用**状态机**切题（不是一把梭正则，可读可调）：

```java
// 题型段落标记
private static final Pattern SECTION = Pattern.compile(
    "^\s*[一二三四五六七八九十]+\s*[、.]\s*(单项选择|多项选择|判断|填空|名词解释|简答|计算|论述)");
// 题号
private static final Pattern Q_NO = Pattern.compile("^\\s*(\\d{1,3})\\s*[.、．)）]\\s*(.+)$");
// 选项：A. A、 A． (A) A）
private static final Pattern OPTION = Pattern.compile("^\\s*([A-F])\\s*[.、．)）]\\s*(.+)$");
// 答案与解析
private static final Pattern ANSWER = Pattern.compile(
    "^\\s*(【答案】|答案[:：]|正确答案[:：])\\s*(.+)$");
private static final Pattern ANALYSIS = Pattern.compile(
    "^\\s*(【解析】|解析[:：]|分析[:：])\\s*(.+)$");
```

**PDF 额外处理**（自考资料 PDF 常见坑）：
- 页眉/页脚/页码清洗：按"每页重复出现的行"自动识别并删除
- 双栏排版：PDFBox 按 `TextPosition` 的 x 坐标聚类，先左栏后右栏
- 扫描件（纯图片）：PDFBox 抽不出字 → 走 OCR 分支

**HTML**：jsoup 去脚本/样式，按 `p`/`div`/`br` 转行，再进同一个状态机。

### 5.4 截图 / 图片

两条路，按性价比选：

| 方案 | 做法 | 适合 |
|---|---|---|
| A. OCR 辅助（推荐） | 接本地 PaddleOCR（Python，一次性装好，中文识别率远高于 Tesseract）或在线 API，识别后进校对工作台 | 截图量大、排版规整 |
| B. 边刷边录 | 提供一个"快速录题"页：左侧贴截图（Ctrl+V 直接存图），右侧填答案，30 秒一题 | 零散截图、OCR 效果差 |

> 建议：**先做 B，OCR 留到 M4**。因为录题时你顺便就复习了一遍，心理成本比校对一堆乱码更低。

### 5.5 校对工作台（决定导入体验成败）

必备的小交互：
- `Tab` 在字段间跳，`Ctrl+Enter` 保存并下一题，`Alt+←/→` 切题
- 批量操作：选中多题 → 统一设置章节 / 来源 / 难度 / 题型
- 全局查找替换（PDF 常有"（）"全角半角混用、"搮"这类 OCR 错字）
- 左侧原文定位跟随，右侧改动即时回写预览
- 离开页面自动草稿保存

### 5.6 校验规则

| 级别 | 规则 | 处理 |
|---|---|---|
| ✖ 阻断 | 无题干 / 无答案 / 单选答案不在选项里 / 多选题选项 < 2 | 必须修 |
| ⚠ 警告 | 疑似重复（hash 或题干相似度 > 0.9）/ 题干过短 / 解析为空 / 章节为空 | 可跳过 |
| ℹ 提示 | 选项数异常（单选 2 个选项）/ 含未闭合公式 `$` / 含乱码字符 | 建议检查 |

### 5.7 多资料统一入库与自动归类

网盘里不只有"题库"，而是**历年真题、教材、讲义/PPT、知识点笔记混在一起**。这一节解决三件事：认得出是什么、分得清属于哪门课、各归各位。

**核心原则：一份资料 ≠ 一种用途。**

同一本教材，既是章节树的来源，也是答案解析的"溯源依据"；同一份真题，既产出题目，也产出高频考点。所以入库的产物是**资产**，不是"把文件搬到某个文件夹"。

| 资产 | 来自哪些资料 | 用来干什么 |
|---|---|---|
| **题目** Question | 真题、习题集、题库 | 刷题、判分、错题本 |
| **章节树** Chapter | 教材目录、讲义大纲 | 组织题库、算进度、看掌握度 |
| **知识点** KnowledgePoint | 讲义、笔记、真题解析 | 打标签、薄弱分析、复习卡片 |
| **原文块** Block | 教材、讲义全文 | 解析溯源"看教材原文"、全文检索 |

#### 自动归类流程

```
选择文件夹（递归扫描）
      │  SHA1 去重（同一份资料重复下载很常见）
      ▼
┌─────────────────────────────────────────────────────────┐
│ ① 资料类型识别   REAL_PAPER / EXERCISE / BOOK / LECTURE  │
│                 / NOTES / OTHER   + 置信度                │
├─────────────────────────────────────────────────────────┤
│ ② 学科识别       目录名 → 文件名 → 课程代码 → 内容词频     │
├─────────────────────────────────────────────────────────┤
│ ③ 用途分流       不同类型走不同解析器，产出不同资产        │
└─────────────────────────────────────────────────────────┘
      ▼
 人工确认（只确认低置信度的，高的批量放过）
      ▼
 后台任务队列解析 → 入库 → 资料库可追溯 / 可整份下线
```

#### ① 资料类型怎么判断

**不靠猜，靠证据叠加。** 每命中一条加分，总分映射成置信度：

| 类型 | 强信号（文件名 / 路径） | 结构信号（打开后看） | 产出 |
|---|---|---|---|
| `REAL_PAPER` 历年真题 | 真题、历年、试题、试卷、统考、2023.4、10月 | 【答案】密度高；出现"一、单项选择题"；有分值 | 题目 + 年份 + 分值 |
| `EXERCISE` 习题/题库 | 习题、练习、题库、模拟、押题、密训 | 题号连续、答案集中成段 | 题目 |
| `BOOK` 教材 | 教材、教程、课本、大纲 | 目录层级深、段落长、章节编号规范 | 章节树 + 原文块 |
| `LECTURE` 讲义/PPT | 讲义、课件、PPT、精讲、串讲 | 页数少、短句、项目符号多、图多 | 知识点 + 原文块 |
| `NOTES` 知识点/笔记 | 考点、知识点、笔记、速记、口诀、总结 | 条目化、表格多、篇幅短 | 知识点卡片 |
| `OTHER` | — | — | 仅存档，不解析 |

- 置信度 < 0.6 → **标黄进入"待确认"**，不静默入库
- 理由：把一本教材误判成题库，会解析出几千条垃圾题目，清理成本远高于多点一次确认
- 规则表 `classify_rule` 做成可编辑的（正则 + 目标类型 + 权重），你自己的命名习惯可以慢慢"训练"它

#### ② 学科怎么认（重点：学科名你自定义）

- 学科表加 `aliases` 字段：`马克思主义基本原理` 的别名可以是 `马原`、`03709`、`马原概论`
- 匹配顺序：**文件所在目录名 → 文件名 → 自考课程代码（5 位数字，强特征）→ 内容前 2000 字的关键词**
- 匹配不上时，界面直接建议「新建学科：马克思主义基本原理（来自目录名）」，一键创建并自动写入别名
- 所以：**先建学科（或让导入向导帮你建），再导资料**，不用你手动一道道归类

#### ③ 章节树怎么来（决定后面所有体验）

- 首选**教材目录**：PDF 书签 / 目录页、docx 的 Heading 1/2、pptx 的幻灯片标题，都能直接生成多级树
- 多份资料合并：以教材树为**骨架**，讲义的标题往骨架上"挂"；挂不上的进「待归类」箱，人工拖拽
- 真题的章节归属：解析出的知识点关键词 → 匹配章节名/知识点；低置信度的批量指派
- 树可编辑：拖拽排序、重命名、合并；「重新导入目录」时按 path 匹配，**已刷的记录不丢**

> 自考的教材换版会让章节变化，所以章节树是"可重建的派生数据"，题目和答题记录不受影响。

#### ④ 知识点与"看教材原文"

- **M2 阶段不做抽取**，只做「原文块 + 全文检索 + 溯源」——成本最低、价值最大。刷题答错时点「查看教材原文」，直接跳到教材对应段落
- **M3 再做知识点卡片**：从讲义/笔记里按标题层级 + 项目符号抽出「标题 + 3~5 条要点」
- **M4 可选接 LLM**：给前 2000 字让模型输出 `{type, subject, chapters[]}`，或给题目自动打知识点标签。做成可插拔 Provider（OpenAI 兼容接口 / 本地 Ollama），**默认关闭也能完整使用**
- 判断题干来源：`question_source` 表记录「这份题来自哪份资料的第几页」，以后发现答案错了能一键翻回原文核对

#### ⑤ 支持的格式与解析器

| 扩展名 | 解析器 | 说明 |
|---|---|---|
| `.xlsx` `.xls` `.csv` | POI / 自写 CSV | 最省事，优先用模板 |
| `.docx` | POI XWPF | 标题样式 → 章节树；正文 → 状态机切题 |
| `.doc` | ⚠️ 建议先另存为 docx | 老格式 POI 支持很差，别硬啃 |
| `.pptx` | POI XSLF | 每页 = 标题 + 正文 + 图片，天然适合抽知识点 |
| `.ppt` | ⚠️ 建议转 pptx | 同上 |
| `.pdf` | PDFBox | 有文本层直接抽；扫描件走 OCR（可选） |
| `.txt` `.md` | 直读 | — |
| `.html` | jsoup | — |
| 图片 | 录题页 / OCR | 见 5.4 |

#### ⑥ 任务队列与资料库

- 一次选一个文件夹，递归扫描；文件哈希去重，重复文件直接跳过并提示
- 解析放后台线程（2~3 并发），页面显示进度、当前文件、预计剩余
- 每个文件产出 `ImportReport`：成功 N 题 / 警告 N 条 / 失败原因，可导出 CSV 慢慢修
- 「资料库」页按学科/类型筛选，每条显示：**这份资料贡献了 128 道题 / 23 个知识点 / 460 段原文**
- 整份资料可以「下线」：连带删除它导入的题目（二次确认），原始文件仍留档

#### ⑦ 冲突怎么处理

| 情况 | 处理 |
|---|---|
| 同一道题在真题和习题集里都出现 | 题干 hash 去重，保留最早一条，`source` 合并成多来源 |
| 同一份资料重复下载 | SHA1 命中，直接跳过 |
| 章节名在教材/讲义里不一致 | 以教材为准，讲义标题作为别名挂到同一节点 |
| 真题年份解析不出来 | 用文件名/目录名兜底，仍失败则留空，不影响做题 |

## 6. 核心业务规则

### 6.1 题型枚举与判分

| 分组 | 类型 | 判分方式 |
|---|---|---|
| 客观 | `SINGLE` 单选、`JUDGE` 判断 | 全等 |
| 客观 | `MULTIPLE` 多选 | 策略可配：`ALL_OR_NOTHING`（默认，自考常用）/ `PARTIAL`（少选得半分，错选 0）|
| 半客观 | `FILL` 填空 | 答案归一化（去空白/全半角/大小写/中英标点）后与"可接受答案集合"比对，支持多空 |
| 主观 | `TERM` 名词解释、`SHORT` 简答、`CALC` 计算、`ESSAY` 论述 | 不自评分数，只自评掌握度；展示参考答案 + 关键词高亮 |

主观题自评选项（映射到记忆算法）：
- 🟢 **答对了** → `MASTER`，间隔 ×2.5
- 🟡 **有印象但不全** → `VAGUE`，间隔不变
- 🔴 **完全不会** → `NONE`，重置为 1 天并进错题本

> 不要做"AI 自动判主观题"。自考主观题按点给分，模型判分误差大且不稳定，反而干扰复习判断。关键词提示可以做：把参考答案里的名词做成标签，你答完自己对照。

### 6.2 七种练习模式

| 模式 | 入口 | 行为 |
|---|---|---|
| 章节练习 | 学科 → 章节 | 按章节顺序/乱序，可设题量；答完立即判分并展开解析 |
| 随机练习 | 学科首页 | 全学科/指定章节/指定标签随机抽题，可勾选"只做没做过的" |
| 模拟考试 | 试卷列表 | 整卷、倒计时、不即时判分、交卷后统一出分，答题卡可跳题 |
| 错题重练 | 错题本 | 默认按"错误次数"排序；答对 2 次移出错题本（可配） |
| 收藏练习 | 收藏夹 | 手动收藏的题 |
| 每日复习 | 首页 | `review_state.due_at <= now` 的队列，按 SM-2 排 |
| 背题模式 | 任意题集 | 直接显示答案，左右滑/键盘"会/不会"，不判分，快速过题 |

所有模式**共用一套答题引擎**，只是配置不同 → 开发量省一半。

### 6.3 间隔重复（SM-2 简化版）

```
答对: interval = (reps==0 ? 1 : reps==1 ? 3 : round(interval * ease))
      ease = ease + 0.1  (上限 3.0)
答错: lapses++, reps=0, interval=1, ease = max(1.3, ease-0.2)
主观自评: MASTER 等同答对；VAGUE ⇒ interval 不变；NONE 等同答错
上限: interval ≤ 180 天
```

- 首页"今日待复习 N 题"就是 `due_at <= 今天` 的数量
- 复习队列一次最多 30 题，避免"欠账 800 题"直接劝退
- 将来想升级 FSRS，只换 `ReviewScheduler` 一个接口的实现，数据结构加两个字段即可

### 6.4 答题交互细则（体验的关键）

| 场景 | 决策 |
|---|---|
| 单选/判断 | 点选项即选中；**默认"选完立即判分并展开解析"**，可在设置里改成"点下一题才判"（有人喜欢先检查一遍） |
| 多选 | 选项为勾选态，必须点"确认"才判分（防止手滑） |
| 主观题 | 输入框（可只写关键词）+ "对照参考答案"按钮 → 展开答案 + 三个自评按钮 |
| 判分反馈 | 正确：选项变绿 + 轻震动（手机）+ 音效（可关）；错误：你的选项红、正确项绿、自动展开解析 |
| 答错自动 | 自动进错题本、自动降 `ease`、自动排进明天复习 |
| 键盘 | `1~9` 选选项、`Enter` 下一题、`←/→` 切题、`F` 收藏、`N` 笔记、`Space` 显示解析、`Esc` 退出（有确认） |
| 手机手势 | 左右滑切题（可关，避免和选项滑动冲突）、底部大按钮吸底、适配安全区 |
| 断点续答 | 退出/刷新/换设备 → 回首页显示"继续上次练习（12/40）" |
| 答题卡 | 网格，颜色区分：灰=未答 / 蓝=已答 / 橙=标记 / 红=答错 / 绿=答对（模考中不显示对错） |
| 长题干 | 字号可调 3 档（15/17/19px），行高 1.8；暗色模式跟随系统 |
| 误触保护 | 交卷、清空、退出未完成练习都要二次确认 |

### 6.5 组卷器与「按题型专项」

同一个组卷接口，支撑所有"我想练哪一批题"的需求：

```
学科：操作系统
题型：☑ 单选  ☑ 多选  ☐ 填空  ☑ 简答  ☐ 综合
范围：☑ 全部章节  ☐ 指定章节（树形多选）
年份：2015 ~ 2024
来源：☑ 真题  ☐ 习题集  ☐ 讲义自测
其他：☑ 只做错过的  ☐ 只做没做过的  ☑ 打乱顺序  ☐ 打乱选项
数量：30
```

三个必须做对的细节：

- **打乱选项要同步重映射答案**：`A→C` 之后 `answer` 也要跟着改，这是很多刷题工具的 bug 来源
- **主观题默认走自评**，不硬判分；组卷时可以把主观题排除，做纯客观题速刷
- **真题整卷**和**拆散重练**共用同一批题，通过 `paper` 表保留原始卷面结构（题号、分值、大题标题）

### 6.6 知识点学习（与刷题并列的一级模块）

**定位**：刷题解决"会做题"，知识点解决"真的懂"。两者共用同一套记忆调度，不是两个割裂的功能。

#### 学习闭环

```
浏览章节 → 卡片流学习 → 即时测试（3 道关联真题）→ 更新掌握度
   ▲                                              │
   └──────── 间隔重复队列（到期提醒） ◀────────────┘
```

#### 卡片结构

| 字段 | 说明 |
|---|---|
| `title` | 如「辛亥革命的历史意义」 |
| `summary` | 3~5 条要点，Markdown，每条一行、短句 |
| `source_block_id` | 可跳回教材/笔记原文对应页 |
| `exam_refs` | 关联真题数（点开能看具体题目） |
| `chapter_id` | 挂在章节树上，和题目同一套章节 |
| `status` | `DRAFT` 自动生成待校对 / `PUBLISHED` 已确认 |

#### 三种进入方式

| 入口 | 场景 |
|---|---|
| 知识点 → 章节 → 开始学习 | 系统学一整章 |
| 首页 → 今日复习（混合队列） | 每天清到期卡片 |
| 刷题答错 → 「考的是：xxx」 | 错题反查，即时补漏 |

#### 卡片流交互（决定好不好用）

- 一屏一张卡：标题 + 全部要点直接显示（自考知识点不适合"翻面猜"，看懂比回忆更重要）
- 底部三档：`不会` / `模糊` / `会了` → 映射 SM-2 的 q=1/3/5
- 手机：左滑"不会"、右滑"会了"；键盘：`1/2/3` 评分、`空格` 下一张、`←` 回上一张
- 顶部进度条 + 剩余时间预估（18 张 ≈ 6 分钟），让人愿意"再来一组"
- 每张卡右上角「关联真题 12 道」，点开就能看题，学完马上验证
- 一组学完 →「测一测这章」→ 抽 3~5 道关联真题；答对才把这组标为「已掌握」
- 卡片可以加自己的笔记（和题目笔记同一个表结构）

#### 统一复习队列

`review_state` 用 `item_type` 区分 `QUESTION` / `KNOWLEDGE`，首页的「今日待复习」是混合队列：

```
今天要复习 42 项
├─ 36 道题（错题 + 到期题）
└─ 6 个知识点（到期卡片）
        → 全部清掉才算完成今日任务
```

#### 掌握度怎么算

- 知识点掌握度 = 关联题目的加权正确率 × 最近一次复习质量（0~100）
- 章节掌握度 = 该章知识点掌握度的均值；没有知识点时退化为题目正确率
- 低于 60% 的章节在首页标红，直接给「补这一章」按钮

#### 页面

- `/points`：左侧章节树 + 右侧卡片列表（掌握度、关联题数、上次复习）
- `/points/:id`：卡片详情（要点 / 原文出处 / 关联真题 / 我的笔记）
- `/points/learn?chapterId=`：卡片流（全屏专注模式）
- `/points/review`：知识点复习队列

#### 生成方式（三源合一）

1. 官方笔记（按章分的 PDF）→ 一章一卡组
2. 通关宝典 / 讲义（有目录树）→ 按小节切分
3. 真题的 `【考点】` 字段 → 反查建立「知识点 ↔ 题目」映射
4. 抽不出来的进「待整理」箱，人工补 3 条要点（一条 30 秒）

> 自动生成的一律是 `DRAFT`，你在卡片详情里点「确认」才转 `PUBLISHED` —— 知识点错的代价比题目更大。

> 详细的数据依据见 `资料盘点与导入策略.md`。

### 6.7 刷题与知识点的边界（v0.2 调整）

明确一条产品规则：**选择题用来刷，主观题用来背。**

| 题型 | 去向 | 交互 |
|---|---|---|
| 单选 `SINGLE`、多选 `MULTIPLE`、判断 `JUDGE` | **刷题** | 点击选项 → 立即判分 → 看解析 |
| 填空 `FILL`、名词解释 `TERM`、简答 `SHORT`、计算 `CALC`、论述 `ESSAY` | **知识点卡片** | 先看题干回想 →「显示答案」→ 三档自评（不会 / 模糊 / 会了） |

为什么这样分：

- 选择题能可靠自动判分，适合高频、快节奏地刷
- 主观题判分不可靠，强行判分反而干扰复习判断；按"卡片 + 自评"进入间隔重复，才符合记忆规律
- 两类内容共用同一个 `review_state`（`item_type = QUESTION / KNOWLEDGE`），首页"今日待复习"可以混合统计

实现上不新增表：**知识点卡片 = `question` 表里主观题的那部分**，
`GET /api/cards` 直接查出来，`POST /api/cards/{id}/review` 写 `KNOWLEDGE` 的复习状态。
以后要加"纯手写知识点"（不对应某道题），再引入独立的 `knowledge_point` 表。

组卷时默认只取三种选择题；将来组卷器里的"题型"勾选项也只列这三种。

### 6.8 缺答案与补答案（v0.3 新增）

现状：大量老试卷的答案只存在于扫描图片里（文件名写「答案在试卷后」，但 `.doc` 的文字层里没有答案）。
所以题库里必须允许「有题无答案」的中间状态：

- `question.status = 'NO_ANSWER'`：结构完整（题干 + 选项）但答案缺失，**不进刷题池、不进组卷**
- 补上答案后自动转 `ACTIVE`
- 导入时如果同目录存在纯「参考答案」文件（文件名含"答案"但不含"真题/试题/试卷/题目/解析"），
  按文件名里的考期（`2024-10`）配对，按题号回填

补答案的交互按**整套卷子**组织，而不是混在一起随机抽题：

1. `GET /api/questions/pending/sources?subjectId=` 先列出「哪几套卷子还有多少题没答案」
2. **答案图直接显示**：`GET /api/answer-images?source=` 会把原始 `.doc/.docx/.pdf` 里内嵌的图片抽出来
   （HWPF PicturesTable / docx 的 `word/media` / PDF 的 XObject），过滤掉近乎空白的页，
   整页竖版扫描图排在最前面，缓存到 `data/answer-images/{hash}/N.jpg`。
   这样绝大多数「答案在试卷后」的卷子不用再手动去翻原始文件
3. 题目补了 `qno`（卷面题号）：导入时写入，历史数据由 `QnoBackfill` 重解析原始文件后用 hash 回填
4. 逐题模式：点选项即保存，数字键 1-9 快速选
5. 批量模式：桌面端左边看答案图、右边粘贴，三种写法——
   带题号 `22A 23B 24C`（最稳，可直接照答案图抄全卷，已有答案的题号会被自动忽略）、
   勾选「按整卷题号排」后填 `B C A D …`（第 1 个答案对应第 1 题）、
   或按待补列表顺序填 `A B C AB D`；
   判断题接受 `T/F`、`对/错`、`√/×`，多选自动排序去重
6. 粘贴时列表会实时显示「题号 → 答案」预览，能立刻看出有没有对错位
7. **OCR 自动识别**：`GET /api/answer-images/ocr` 用 Tesseract（只白名单数字 + A-D）识别答案图，
   按「答案页是网格、题号连续」的假设用版面位置推题号，不依赖 OCR 读对题号；
   PSM 6 / PSM 4 两种版面分析各跑一遍，只保留两边一致的答案，识别不出的留空。
   识别结果写进 `data/answer-images/{hash}/ocr.txt` 缓存。
   逐题补模式下用它做即时对错反馈：选完答案和识别结果一致 → 直接保存；
   不一致 → 不落库，弹「你选 A / 答案图是 B」，由用户决定填哪个

### 6.9 错题本（v0.3 新增）

定义：**最近一次作答为错**的题（`answer_record` 里该题最后一条 `is_correct = 0`）。
答对之后自动离开错题本，不需要手动"移出"。

- 只统计三种选择题；主观题的自评结果不算错题
- `GET /api/wrong/summary` 给各学科错题数，`GET /api/wrong?subjectId=` 给列表
- 「刷这些错题」复用 `POST /api/practice/sessions { onlyWrong: true }`，不新增表

### 6.10 组卷器（v0.4 新增）

`POST /api/practice/sessions` 扩展成可精细组卷，不新增表：

- `types`：题型多选（SINGLE / MULTIPLE / JUDGE），不传=全部
- `years`：年份多选，不传=全部年份
- `onlyWrong`：只取「最近一次作答是错」的题（和错题本同口径）
- `onlyNew`：只取从未作答过的题
- `shuffle=false`：按年份倒序 + 题号顺序出题（适合整套真题顺序刷）
- 题量按实际匹配结果自动收缩，不会因为要 50 题只有 30 题就报错

`GET /api/practice/options?subjectId=` 给组卷页用：各题型题量、各年份题量、错题数、没做过数，
前端据此实时显示「预计可组 X 题」。`mode='CUSTOM'` 的 session 在答题页标题显示「自定义练习」。

### 6.11 题库管理（v0.4 新增）

解决「导入解析错了、OCR 补错了，但没有界面能改」的问题：

- `GET /api/questions?subjectId=&type=&status=&q=&year=&source=&page=&size=`：
  分页搜索，`q` 会同时匹配题干 / 答案 / 来源；`status` 区分 `ACTIVE` 和 `NO_ANSWER`
- `PATCH /api/questions/{id}`：改答案 / 解析。选择题走和补答案同一套 `validate()`（多选排序去重、
  判断转对错）；答案清空则退回 `NO_ANSWER`，不会留下"有状态没答案"的脏数据
- `DELETE /api/questions/{id}` / `POST /api/questions/delete`：删题时连带删除
  `answer_record` 和 `review_state`，避免统计和错题本里出现孤儿记录
- 前端 `/bank`：筛选 + 列表（题号/年份/来源/答案/无答案标记）+ 弹层编辑，手机端自动单列

### 6.12 今日复习（v0.4 新增）
选择题原来只在作答时写 `review_state`，但没有任何入口去消费到期队列。现在：

- `POST /api/practice/review?limit=30`：查 `review_state(item_type='QUESTION', due_at <= now)`，
  join 出 `ACTIVE` 的选择题，按到期时间排序拼成一套 session；跨学科，`subject_id=0`，
  展示名固定为「综合复习」，答题页标题显示「今日复习」
- 答题仍走原来的判分 + `reviewService.apply()`，答对间隔 1→3→×ease 天，答错重置为 1 天
- 首页「选择题待复习」数字和「复习 N 题」按钮共用这个接口；没有到期题时接口返回
  「今天没有到期的题」，不会建空 session
- 结果页「再练一组」对综合复习会话会继续调用复习接口，而不是拿 `subjectId=0` 去组卷

### 6.13 模拟考试（v0.4 新增）

复用练习 session，不改表：

- 建卷时 `mode='EXAM'`、`durationMinutes=150`（5~300 分钟），时长写进 `session.config`
- `SessionView` 多返回 `startedAt` + `durationMinutes`，前端据此算截止时间（刷新/重开页面计时不重置）
- 答题页考试模式的行为差异：
  - 选答案只提交、**不显示对错和解析**（`judged` 保持 false）
  - 不强制「先作答才能下一题」，可以自由跳题、改答案（后端按 session+question upsert）
  - 顶部倒计时，最后 5 分钟变红；到 0 自动交卷
  - 可标记不确定的题，答题卡右上角小圆点标识，图例切成「已答/未答/已标记」
  - 底部常驻「交卷」，未答完会二次确认
- 结果页对 `mode='EXAM'` 显示「考试结束」、得分、及格/不及格（60 分线）
- 前端入口：首页「模拟考试 →」，组卷页也有跳转；`/exam` 配置学科、题量、时长

### 6.14 导入工作台（v0.4 新增）

以前导入只能靠 PowerShell 调 API，现在有页面了（`/import`）：

- `GET /api/import/browse?path=`：浏览 `raw/` 目录，只允许 raw 下的路径（防止任意读盘），
  返回目录/文件、大小、是否可解析
- `POST /api/import/scan`：**预检**，完整跑一遍解析（含同目录参考答案按考期对齐）但**不写库**，
  返回每份文件的：解析题数 / 可直接导入 / 待补答案 / 跳过 / 是否扫描件 / 前 3 题样例
- `POST /api/import/dir`：正式导入，结果按文件列出新增/跳过/待补
- `GET /api/import/batches` + `POST /api/import/rollback/{id}`：导入历史与整批回滚，
  回滚会删掉该批次导入的题以及它们的 `answer_record` / `review_state`
- 页面会按 raw 顶层文件夹名自动猜学科（如「4747Java语言程序设计（一）」→ Java），
  并在导入按钮旁明确显示「将导入到「X」」，避免导错学科

### 6.15 AI 答案校验（v0.4 新增）

用大模型给题库做一遍「独立作答」，和现有答案比对，人工决定是否采纳：

- 接口走通用的 OpenAI 兼容协议（`/chat/completions`），所以 DeepSeek、智谱、SiliconFlow、
  本地 Ollama 都能直接填地址 + 模型 + Key 使用；配置存 `data/ai.json`
- 同步接口不接受流式；单题 prompt 要求模型只返回 `{"answer":"B","reason":"..."}`，
  解析失败会退化成正则抓字母/对错
- 批量校验在单线程后台跑（每题间隔 120ms，避免触发限流），进度内存维护，前端 1.5s 轮询
- 结果写 `ai_check` 表（`question_id` 唯一），`verdict` 分 `MATCH / DIFF / ERROR`；
  **只有用户点「采纳」才会调用 `QuestionService.update` 改答案**，点「忽略」只改状态
- 免费方案：智谱 GLM-4-Flash、SiliconFlow 的免费模型、本地 Ollama；DeepSeek 便宜但需充值
- 本地 Ollama 地址填 `http://localhost:11434/v1` 时**不需要 API Key**（地址含 localhost/127.0.0.1 自动放行）
- 建议先跑 20 题评估模型水平，再扩大范围；AI 对冷门自考题也会答错，必须人工看

**补答案时单题校验**（`POST /api/ai/check-one`）：

- 逐题补答案时，如果这道题没有答案图可用（或答案图没识别出来），选完选项会自动让 AI 独立做一遍
- 判断题/单选/多选都支持；AI 认为「一致」直接保存，不一致时弹卡片「你选 A，AI 认为 B（理由）」，
  由用户决定按 AI 填、坚持自己的答案或跳过
- 每道题的 AI 结果在服务端缓存 30 分钟，反复改答案不会重复调用
- 补答案页有「AI 校验」开关（配置了 Key 才显示），关掉就回到原来的行为

## 8. API 设计（节选）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/login` | 登录，返回 token |
| GET | `/api/subjects` | 学科列表（含进度摘要） |
| GET | `/api/subjects/{id}/chapters` | 章节树 |
| POST | `/api/sessions` | 创建练习 `{subjectId, mode, chapterIds, count, shuffle, paperId}` → `{sessionId, questions[]}` |
| GET | `/api/sessions/{id}` | 恢复会话（断点续答） |
| POST | `/api/sessions/{id}/answers` | 提交单题 `{questionId, answer, costMs, selfRating}` |
| POST | `/api/sessions/{id}/finish` | 交卷，返回成绩摘要 |
| GET | `/api/sessions/{id}/result` | 结果页数据（得分、错题、章节薄弱度） |
| GET | `/api/review/queue?limit=30` | 今日复习队列 |
| GET | `/api/wrong` | 错题本（按学科/章节/错误次数筛选） |
| GET | `/api/questions?keyword=&type=&chapterId=` | 题库检索（分页） |
| POST | `/api/import/preview` | 上传文件，返回解析预览（不入库） |
| POST | `/api/import/commit` | 提交校对后的题目 |
| GET | `/api/import/batches` | 导入批次（可回滚） |
| GET | `/api/stats/overview` | 首页数据（打卡、正确率、待复习数） |
| POST | `/api/backup` | 生成备份 zip |

**判分位置**：本地单机 + 局域网场景，**题目包直接带答案，前端判分**，服务端只落答题记录。好处是零延迟、断网可续、实现简单；如果将来放公网再改成服务端判分（接口不变，加个 `?serverJudge=true`）。

模板示例：

```json
// POST /api/sessions
{
  "subjectId": 1,
  "mode": "CHAPTER",
  "chapterIds": [12, 13],
  "count": 40,
  "shuffle": true,
  "judgeImmediately": true,
  "includeAnswer": true
}
```

## 11. 风险与取舍

| 风险 | 影响 | 对策 |
|---|---|---|
| 本机是 Java 8 | Spring Boot 3 无法启动 | 装 JDK 21；最终用 jlink 打包自带运行时 |
| PDF 扫描件/复杂排版 | 解析准确率低 | 接受"人工校对"，把校对工具做到 30 秒/题；不追求全自动 |
| 主观题 | 无法自动判分 | 自评 + 参考答案 + 关键词，明确不做 AI 判分 |
| 题库答案本身有错 | 复习被误导 | 每题"报错"按钮 → `errata` 表 → 批量修正；导入时标记低质量来源 |
| 手机访问不了 | 用不起来 | 首页二维码 + 一键复制地址 + 防火墙提示；`server.address=0.0.0.0` |
| 数据丢失 | 前功尽弃 | 每日自动备份 7 份 + 手动导出 zip（含 db 和 media） |
| 题库版权 | 法律风险 | 仅个人复习自用，不做公开分发/上传 |
| 范围膨胀 | 做不完 | 严格执行 M1 闭环，功能进"以后再说"清单 |
