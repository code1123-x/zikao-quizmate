# QuizMate 网页版与微信小程序分析

> 基于当前代码静态走查，重点关注实际学习流程、状态可靠性、功能覆盖与界面体验。本文区分现有问题、已落地改动和后续建议。

## 总体判断

项目已经形成完整的学习主链路：学科和考试计划、题库导入、日常练习、模拟考试、错题、知识点复习及统计。服务端使用 Spring Boot + SQLite，网页版 Vue 3，小程序原生微信框架，两端共享服务端数据。

网页端是功能完整的主要工作台，小程序适合随时练习和查看进度。目前主要短板是：两端能力差异明显、做题状态在网络异常或页面退出时缺少可靠恢复、题库质量反馈不足，以及首页功能入口的优先级还可更贴近“马上开始学习”。

## 功能一致性与首次进入

### 本轮实施记录

- 小程序交卷现在有 `finishing` 状态，阻止用户重复点击交卷；正在提交答案时也不再弹出交卷确认，避免答案保存和交卷请求同时竞争。
- 交卷失败会清除提交中状态，允许用户再次尝试；成功后 `finished` 状态阻止重复提交。
- 网页首次设置增加“稍后设置”，选择后允许进入首页，之后仍可通过考试计划完善；首次向导不再阻断先体验产品。
- 小程序刷题新增填空、名词解释、简答、计算和论述文本输入；对照参考答案后按 `MASTER / VAGUE / NONE` 自评，与服务端及网页端评分规则一致。
- 小程序「我的」页隐藏当前无法在小程序完成的 AI 校验和导入入口，改为说明网页端批量管理能力。
- 小程序模拟考试发现漏题后，可选择跳回第一道未答题，也可确认交卷。
- 网页模拟考试为每道题显示“未作答/保存中/已保存/保存失败”状态，并用每题递增版本号保护异步响应，失败时保留当前选择以便重试。
- 网页和小程序练习现在会保存当前题号、标记/选择状态和文字草稿；重新进入同一练习时可继续，正常交卷后自动清理草稿。
- 小程序开发配置改为使用局域网地址，后端开发启动时监听 `0.0.0.0`，微信开发者工具已实际编译并加载首页和刷题页；调试器显示 0 个错误，剩余提示为开发工具扩展警告。
- 小程序首页将不可直接完成的 AI 校验入口替换为考试计划，并为空题库状态提供“设置考试计划/去导入题库”操作；README 同步更新为当前主观题支持范围。
- 网页侧边栏将“组卷”统一命名为“练习”；原有 `/build` 路由保留，页面内继续提供模拟考试切换入口，减少一级导航重复但不破坏旧链接。
- 网页端和小程序统计页的低正确率学科现在都显示“练薄弱题”，可直接创建该学科的复习练习；网页错题总数也可直接进入错题本，形成从数据到行动的闭环。
- 题库预检结果新增“结构异常/跳过”统计，并明确提示扫描件、缺答案和不合法答案不会直接进入练习，降低导入后才发现题目异常的风险。
- 题库预检进一步按题目哈希识别已有同题，文件明细会显示疑似重复数量；解析器返回的警告也会保留在文件级提示中，便于导入前人工判断。
- 本轮验收通过：网页生产构建成功，后端使用 JDK 21 编译成功，小程序 17 个脚本均通过 Node 语法检查，网页与后端健康地址均返回 200，未登录业务接口按预期返回 401。
- 网页端补充窄屏布局、键盘焦点可见样式、移动端输入字号、长题干换行和减少动画模式；同时修复移动端练习侧栏按钮被基础样式覆盖的问题。
- 小程序现在提供可见的“导入题库”入口，支持从微信聊天文件选择单个题库文件，上传到当前学科并展示新增、跳过、待补答案和文件级处理结果；批量导入与校对仍保留在网页端。
- 后端已使用 JDK 21 重新打包并重启，网页与接口地址均返回 200；网页生产构建通过，小程序答题脚本通过 Node 语法检查。真机调试仍需确认手机与电脑在同一局域网，生产环境需使用 HTTPS 合法域名。
- 练习组卷新增章节筛选，章节选项展示可练题量、错题量和未做量；选择章节后预计题量会跟随题型、错题/未做范围实时更新。

### 两端功能一致性

当前**功能并不一致**。网页导航包含首页、知识点、组卷、模拟考试、题库、错题本、统计和导入；微信小程序页面目录虽然也注册了计划、题库、知识点、模拟考试、AI、导入等页面，但 README 明确标记部分功能尚未放入小程序，且「我的」页又提供了通往这些页面的入口。因此，页面存在不等于能力完整，容易出现点进去无法完成、需要跳回网页的落差。

| 模块 | 网页端 | 小程序端现状 | 一致性判断 |
|---|---|---|---|
| 登录/账号 | 登录、注册、账号设置 | 登录、我的、退出 | 部分一致；账号管理能力需核对 |
| 首次设置/考试计划 | 省份、层次、专业、课程、日期完整配置 | 有计划页面入口；首页空计划提示可进入 | 流程需核实；网页首次向导不应成为小程序的网页专属死路 |
| 日常练习 | 选择题、填空/主观题流程、设置、答题反馈 | 主要支持单选、多选、判断；其他题型提示去网页 | 不一致，影响核心学习 |
| 模拟考试 | 组卷、限时、题号面板、交卷与结果 | 有考试入口和答题页，但导航/漏题提示及状态需对齐 | 部分一致 |
| 知识点复习 | 知识卡片和学习流程 | 有卡片/学习页面 | 应核验排序、复习状态与统计口径 |
| 错题与统计 | 错题管理、统计分析 | 错题本、统计页 | 目标相同，筛选和分析深度需对齐 |
| 题库管理 | 搜索、编辑、删除、导入 | 有题库页；首页提示可管理 | 部分一致；移动端编辑需要明确范围 |
| 导入 | 网页文件夹浏览、预检、导入历史 | 有导入页面入口，但说明写着未支持 | 不一致；需明确是否真的支持微信文件导入 |
| AI 校验 | 网页 AI 校验 | 有入口/页面注册但 README 称暂未放入 | 不一致；入口状态与产品说明冲突 |

建议把“一致”定义成**相同核心任务能在两端完成并共享状态**，而不是要求像素级相同或每个复杂管理控件完全相同。最低完整闭环应为：首次设置、开始练习、各题型作答/自评、错题复习、知识点复习、模拟考试、查看结果、学习统计和计划查看/修改。题库导入、批量校正、复杂专业目录编辑可先共用网页视图或明确标注为桌面增强能力；如果坚持完全原生一致，则需要在小程序实现真正的文件选择和导入校验流程，不能保留空壳入口。

### 首次进入交互评估

网页新用户当前顺序是创建账号后进入省份/层次/专业选择、选择本次科目、设置考试日期，再进入首页。这个向导对目标明确的自考用户有帮助，但把专业、官方目录、课程和考期都作为开始刷题的前置条件，步骤较重；未确定考试日期或只想先试用的人可能被挡住。`App.vue` 检查 `setupStatus` 后会强制跳转 `/setup`，因此这不是可跳过的建议，而是硬门槛。

建议改成**必需项最少、逐步完善**：账号创建后只要求创建/选择一个学科（或先导入题库）；专业和考试计划作为推荐设置，可稍后完成。若当前尚无题目，向导给出“导入题库 / 添加学科 / 查看演示题”明确选项；设置完成后直接回到学习首页。登录老用户仍应保留自动跳过已完成引导的行为。小程序首次登录必须有同等引导，不能仅显示“请先在网页端设置”；移动端可先完成选择学科与计划日期，复杂目录选择再提供打开网页的明确路径和进度保留。

向导可以在首次启动时展示，但首页应保留可再次进入的“考试计划/完善资料”入口。首次进入的目标应该是让用户尽快完成第一道题，而不是一次性填完全部账户资料。

## 功能模块取舍

### 建议保留为核心

- **首页与学习计划**：学习起点、今日目标、考试倒计时和继续练习。
- **日常练习 + 错题复习 + 知识点复习**：形成主要学习闭环，应该两端都可用。
- **模拟考试 + 结果复盘**：自考场景的关键差异能力，需和日常练习区分清楚。
- **题库浏览与搜索**：练习数据可信和查找题目的基础。
- **统计**：保留能引导下一步学习的统计；避免只展示不指导行动的指标堆叠。
- **首次设置/考试计划**：保留但从硬门槛降为渐进配置。

### 建议合并或降级

| 当前入口/模块 | 取舍建议 | 原因 |
|---|---|---|
| 「组卷」与「模拟考试」 | 合并为“练习/考试”入口中的两种模式，或将“组卷”作为模拟考试的设置步骤 | 用户目标相近，分开一级导航会造成概念重叠；若组卷支持独立保存/分享试卷，则保留为高级功能 |
| 首页题库入口与导航题库入口 | 首页只保留每门课的快捷查看，完整管理放在题库模块 | 避免重复入口和首页工具过载 |
| 首页多个统计数字与统计页 | 首页保留今日目标、待复习和连续学习；详细趋势放统计页 | 降低首页认知负担 |
| 设置中的考试日期与考试计划 | 统一由考试计划管理；设置只放账号、显示、练习偏好 | 避免同一数据多个入口和规则不一致 |
| AI 校验 | 降为题库维护工具中的可选能力，不占首页/小程序一级入口；未配置时隐藏或清晰说明条件 | 非每次学习都需要，且依赖模型配置/成本，弱化核心刷题路径 |
| 单独的「学习」页与知识点卡片 | 若学习页只用于逐题查看卡片，统一到知识点复习流程；保留不同的记忆训练玩法 | 减少“知识点/学习/卡片”概念重复 |

### 不建议直接删除的内容

题库导入、AI 校验、主观题学习、专业计划虽然不是每次打开都用，但分别关系到内容来源、题库正确性和自考题型覆盖。建议先从首页和一级导航中降级、收纳或明确标注能力范围；只有在确认没有实际使用场景或功能已有可靠替代后，才删除页面和后端接口。小程序“导入题库”当前尤其需要确认：若还不能从微信文件选择器实际导入，建议暂时移除该入口并提供网页导入指引，避免误导。

### 导航建议

- 网页侧边栏控制在 5 个一级入口：**首页、练习、知识点、错题、题库**；统计放入首页/我的学习，模拟考试作为练习模式，导入作为题库操作，考试计划放顶部或首页卡片。
- 小程序底部 Tab 保留 **首页、学习、我的**；“学习”承载练习、知识点、错题和考试入口，避免把次要管理模块挤进底栏。
- 两端名称、图标含义和入口层级相同。功能暂不可用时不要展示可点击的空壳页面。
- 真正的管理增强功能（专业目录维护、批量导入校对、AI 答案复核）放入“题库管理/更多工具”，并标明端侧支持情况。

## 网页版

### 已有优点

- 首页提供每日目标、连续学习、考试倒计时、课程卡片和复习入口，能引导用户开始学习。
- 练习页具备进度恢复、单题计时、答题反馈、考试倒计时、标记题和题号面板等基础能力。
- 课程删除会先说明影响，对有题目的课程还要求输入名称确认，降低误删风险。
- 全局视觉样式已使用统一颜色、卡片、圆角、阴影、按钮和焦点样式，整体结构清晰。

### 主要不足与建议

| 领域 | 观察到的问题 | 建议 |
|---|---|---|
| 答案保存 | 模拟考试每次选择后立即发请求，快速连续选择可能出现请求乱序；网络错误后答案状态恢复不够明确 | 按题串行保存或做版本号保护；区分“保存中/已保存/保存失败”，失败保留选项并提供重试 |
| 草稿恢复 | 已答进度可以恢复，但当前题、未提交答案、标记题主要保存在页面内存 | 本地保存练习草稿；重新进入时提示继续上次练习或重新开始；考试答案以服务端状态为准 |
| 交卷 | 自动交卷等待忙碌请求时采用轮询；请求卡住或交卷失败时缺少更清楚的恢复提示 | 使用明确的提交状态与超时错误提示；交卷失败允许重试，不要让页面看似已交卷 |
| 练习筛选 | 首页主要是随机开始和复习入口，按章节、题型、未做/错题等组合训练不够直达 | 开始练习前提供轻量筛选，显示匹配题量，保留最近一次筛选 |
| 题目讲解 | 答题效果依赖解析内容完整度，题库无解析时学习闭环弱 | 答案、解析、来源分层展示；无解析时明确显示“暂无解析”，提供收藏/反馈纠错入口 |
| 统计转行动 | 总正确率和总量能看趋势，但不能直接指出薄弱章节和下一步练什么 | 增加章节正确率、近期变化、待复习队列，并让统计卡片可直接进入针对性练习 |
| 空状态 | 新用户无题、无计划或筛选无结果时，需要明确下一步 | 每种空状态配一个主按钮，例如“导入题库”“设置考试计划”“清除筛选” |

### 页面美化建议

- 首页已经有卡片化和渐变视觉，建议进一步突出一个主操作“继续今日练习”，避免多个次要工具入口与主目标抢注意力。
- 学科卡片可把题量、掌握度和待复习数做成清晰的信息层级；“题库管理”作为次要文字入口，避免与“开始练习”同等强调。
- 练习页建议固定题干与答题操作区的视觉层级，长题干/解析滚动时仍能看见保存状态、题号和下一步按钮。
- 增加浅色/深色之外的专注模式可作为后续选项；先保证窄屏布局、键盘操作、对比度和大字号下可用。
- 适度减少大面积渐变和装饰阴影，统一卡片间距与标题字号；让正确、错误、警告颜色同时配有文字标签，避免只靠颜色表达。

## 微信小程序版

### 已有优点

- 首页直接展示考试倒计时、今日练习、正确率、错题、知识点和学科入口，适合移动端快速查看。
- 练习界面操作相对集中，提供答题进度、保存答案、交卷确认和结束成绩。
- 小程序使用原生页面，和网页共用后端，练习记录可以同步。

### 主要不足与建议

| 领域 | 观察到的问题 | 建议 |
|---|---|---|
| 功能覆盖 | README 明确列出小程序暂不支持导题、考试计划设置、AI 校验、主观题/填空题作答 | 短期明确网页版负责管理、小程序负责移动学习；中期补上考试计划查看/轻量编辑及主观题自评 |
| 主观题体验 | 当前碰到非选择题会提示去网页端完成，移动端学习被打断 | 至少支持查看答案与解析、隐藏答案自测和自评；复杂编辑继续留给网页端 |
| 考试操作 | 考试选项需要额外点“保存答案”，与网页端选择后提交的交互不同；无明确“保存失败后重试”状态 | 保持两端术语和状态一致；显式呈现已保存状态，失败时保留选择并展示重试按钮 |
| 题目跳过 | `skipQuestion()` 直接进入下一题；未答题可能被跳过，考试里用户未必意识到漏题 | 增加“暂时跳过”并在进度中区分未答/已答；交卷前提供未答题列表和跳转 |
| 交卷防护 | `finish()` 直接调用交卷接口且未在函数层防止重复调用；自动交卷和用户点击有机会重叠 | 增加 finishing 状态和幂等保护；超时后显示重试选项，成功后禁用再次交卷 |
| 内容适配 | 页面对当前题型做有限支持，长题干、公式和图片题应核实移动端显示 | 为图片/公式保留缩放和横向查看能力；长解析折叠，选项触控面积保持足够大 |
| 首页密度 | 首页统计、工具入口和学科列表都比较重要，连续滚动后开始练习入口可能被挤到较下方 | 顶部突出“继续练习/开始练习”；工具入口收纳为简洁网格，常用学科优先显示 |
| 错误与加载 | 网络请求失败主要依赖 toast，离开页面或弱网时可恢复信息有限 | 页面级错误区域提供重试；加载骨架保留布局；断网后保留当前选择与明确的待同步状态 |

### 页面美化建议

- 小程序首页沿用清爽卡片方向，减少四个工具卡片与统计卡片的视觉竞争，主按钮突出“开始练习”。
- 学科卡片加入紧凑的掌握进度条和清晰的练习按钮；待补题、考试日期作为辅助标签，不要让文字挤成一排。
- 练习页把题型、题号、保存状态放在题干上方的轻量信息栏；选项卡片增加按下反馈和选中态，避免仅靠颜色辨认。
- 交卷按钮与普通“下一题”使用不同视觉层级，并在最后一题清晰说明动作会结束考试。
- 统一网页和小程序的颜色语义、文案、题型名称和按钮动作；小程序可用更大的间距与触控区域适配拇指操作。

## 两端协同建议

| 用户场景 | 网页版定位 | 小程序定位 | 对齐要求 |
|---|---|---|---|
| 日常刷题 | 完整练习设置、长内容阅读 | 碎片练习、续做 | 答题进度和判分规则一致 |
| 模拟考试 | 完整组卷、题号导航、交卷复盘 | 参加考试、查看进度 | 保存状态、漏题提醒和交卷结果一致 |
| 错题复习 | 筛选、批量管理、查看解析 | 快速重做 | 错题移除/掌握状态及时同步 |
| 题库管理 | 导入、校对、维护 | 查询、轻量纠错入口 | 来源、答案、解析显示一致 |
| 统计计划 | 完整配置和分析 | 查看今日目标、倒计时 | 数据口径和日期计算一致 |

建议建立一份共享验收清单，每次改动接口或练习流程时，至少覆盖两端的创建练习、恢复已答、提交失败、切题、交卷和错题复习。

## 优先改进顺序

1. **P0：答题与交卷可靠性。** 修复网页考试答案请求可能乱序的问题；小程序添加防重复交卷、失败恢复与漏题导航。
2. **P1：两端都能顺畅继续学习。** 保存未提交草稿和当前题号；提供弱网、刷新、重进后的恢复提示。
3. **P1：小程序主观题可学习。** 先支持答案/解析查看与自评，减少“去网页端完成”的中断。
4. **P1：练习入口和筛选。** 增加按章节、题型、错题/未做题练习，并展示可练题量。
5. **P2：提升导入可信度。** 导入预览标出缺答案、重复题、识别不确定内容，避免错误答案进入练习。
6. **P2：统计引导学习。** 从总量展示扩展到薄弱章节、复习队列和一键专项练习。
7. **P2：统一视觉和文案。** 统一两端题型、保存状态、按钮命名与颜色语义，按网页和移动端分别优化布局。
